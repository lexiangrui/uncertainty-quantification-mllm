# 人类对齐流程

## 目录口径

两个 LLM Judge 的原始结果并列保存，不直接作为正式标签：

- GPT-5.6-Terra：`results/judging_gpt_5_6_terra/`
- Gemini-3.7-Flash：`results/judging_gemini_3_7_flash/`
- 人类盲裁工作区：`results/human_alignment/`
- 最终正式标签：`results/judging/`

指标、LUH 子集和 ERA 等下游流程仍读取 `results/judging/`。在全部分歧完成裁决前，正式目录不会生成。

## 生成盲裁队列

```bash
python scripts/human_alignment/prepare.py
```

程序要求两个 Judge 的模型/数据集文件齐全、样本集合相同、`greedy_run` 相同且每条标签有效。它分别统计：

- `correct` 不一致的正确性裁决；
- `hallucination` 不一致的幻觉裁决；
- 两个维度同时不一致的交集。

同一样本即使两个维度都冲突，也只在队列保存一次。重新执行 `prepare.py` 会保留内容未变化样本的已有人工标注。程序会从数据集复制待裁样本图像；任何应载入样本缺失、数据集读取失败或图像保存失败都会中止准备流程，不能降级为“无图样本”。`--skip-images` 仅供自动化测试使用，使用它生成的工作区不能启动裁决前端。

## 前端裁决

```bash
python scripts/human_alignment/serve.py
```

浏览器打开 `http://127.0.0.1:8765`。界面不展示两个 Judge 各自的标签，只展示冲突维度、图像、问题、参考答案和候选回答。正确性和幻觉分区分别给出最终二值标签，幻觉还可补充视觉/推理类型。保存请求按操作顺序串行处理，并在进程/线程之间加文件锁，最终原子写入 `results/human_alignment/annotations.json`。

若前端运行在集群上，在本机建立 SSH 转发后访问同一地址：

```bash
ssh -L 8765:127.0.0.1:8765 mg01
```

## 生成正式结果

```bash
python scripts/human_alignment/finalize.py
```

合并规则：一致维度使用双 Judge 共识，不一致维度使用人工标签。程序会校验原始文件哈希，防止队列生成后原始结果被改动；任何必填裁决缺失时拒绝输出；若 `results/judging/` 已存在也拒绝覆盖。成功后一次性生成完整正式目录，并记录来源哈希和人工标签来源。

## 一致性统计

正式结果生成后，使用以下命令从两个原始 Judge 目录与人工工作区重算一致性和仲裁工作量：

```bash
python scripts/analysis/judge_reliability.py
```

程序输出 `results/analysis/judge_reliability/dual_judge_agreement.csv`、`human_adjudication_counts.csv` 与 `judge_reliability.json`，包括模型级及总体的字段 agreement rate、Cohen's κ、冲突字段数、双字段冲突数和进入人工仲裁的唯一样本数。
