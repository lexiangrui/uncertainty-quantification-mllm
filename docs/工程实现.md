# 多模态大模型不确定性量化工程实现

本文档只描述当前仓库已经保留并完成的第一阶段工程，不包含已删除的实验路线或尚未实现的第二阶段方法评测。

## 1. 当前实验范围

第一阶段覆盖 3 个模型、3 个数据集、3 种 UQ 方法：

| 类别 | 当前配置 |
| --- | --- |
| 模型 | LLaVA-1.5-7B、Qwen2.5-VL-7B-Instruct、InternVL3.5-8B-HF |
| 数据集 | ViLP、HallusionBench、MM-Vet |
| UQ | Perplexity、Semantic Entropy、UMPIRE |
| 回答 | 1 条 greedy 主回答 + 5 条随机采样回答 |
| Judge | 闭源 Judge、开源 Qwen Judge、规则 Judge；Semantic Entropy 使用 NLI Judge |

正式结果位于 `results/`，运行标签为 `full_transformers_k5`。当前仓库已完成生成、UQ、Judge、指标计算和结果分析，三个模型的正式 LoRA adapter 也已保存。

## 3. Prompt 与版本记录

Prompt 不再以内嵌字符串作为唯一来源：

- 生成 Prompt：`prompts/generation/xml_lora_zero_shot_v1.md`
- LoRA 训练 Prompt：`prompts/LoRA/xml_lora_instruction_v1.md`
- LoRA 教师 Prompt：`prompts/LoRA/teacher_prompt.md`
- LoRA few-shot 示例：`prompts/LoRA/few_shot_examples.json`
- 闭源 Judge Prompt：`prompts/judge/closed_source_correctness_hallucination_v1.md`

生成代码、闭源 Judge 和 LoRA 训练代码启动时显式读取对应文件。生成 JSONL 的 `run` 记录保存 `prompt_version` 与 `prompt_sha256`；Judge JSONL 保存 `judge_prompt_version` 与 `judge_prompt_sha256`；LoRA 的 `training_config.json` 保存 `prompt_version` 与 `prompt_sha256`。Prompt 内容变化必须创建新的版本文件，不覆盖已有版本。

## 4. 生成流水线

入口为 `scripts/generation/generate_responses.py`，Slurm 模板为 `slurm/generation/generate_responses.sbatch`。每个模型均要求显式提供基础模型目录和对应 adapter：

```bash
python3 scripts/generation/generate_responses.py \
  --dataset vilp \
  --dataset-source /opt/lexiangrui/datasets/vilp/ViLP.parquet \
  --model-family llava_1_5 \
  --model-path /opt/lexiangrui/models/llava-1.5-7b-hf \
  --adapter-path results/lora/vqav2_5000_4to1/llava-1.5-7b \
  --output results/generation/example/llava-vilp.jsonl
```

生成器将数据转换为统一的 `BenchmarkSample`，写入一条 greedy 回答和五条随机采样回答。每条回答保存原始文本、XML 三段解析结果、格式状态和采样元数据；运行记录保存模型、数据集、生成参数、Prompt 版本和全局 seed。默认使用 `k5` 配置，不能将不同采样数量的结果混入正式运行。

解析器要求 `<vision>`、`<reasoning>`、`<answer>` 各出现一次、顺序固定、内容非空且标签外无文本。解析失败时保留原始回答并标记无效，不猜测、不自动修复。

生成结果支持按 `sample_id` 断点续跑。已有输出的运行配置不一致时直接拒绝继续写入。模型只在存在未完成样本时加载；完全完成的运行不会重复加载权重。

## 5. UQ 流程

UQ 独立入口为 `scripts/uq/compute_uq.py`，Slurm 模板为 `slurm/generation/compute_uq.sbatch`。它读取生成 JSONL 以及 UMPIRE 所需的 `results/hidden/` 输入，输出统一的 UQ JSONL：

- Perplexity：最终答案 token 的 mean NLL 与 PPL；
- Semantic Entropy：对采样答案进行严格双向 NLI 聚类后计算语义熵；
- UMPIRE：使用采样答案最终 token 的末层 hidden vector 计算不一致度。

生成阶段不保存完整 logits、token 序列、KV cache 或完整 hidden states。`results/hidden/` 仅保存 UMPIRE 需要的最终答案末 token 末层 float16 向量。UQ 计算中的 DeBERTa NLI 模型通过 `NLIJudge` 加载，不再由 Semantic Entropy 维护独立 entailment 类。

## 6. Judge 流程

统一 Judge 位于 `src/llm_judge/`，对外保留以下类别：

1. `ClosedSourceJudge`：通过 OpenAI SDK Responses API 调用闭源/托管模型；Prompt 来自 `prompts/judge/`。
2. `OpenSourceJudge`：通过模型名称切换 Qwen 后端。`Qwen2.5-3B-Instruct` 和 `Qwen3-4B-Instruct-2507` 使用文本后端，`Qwen3.6-VL` 使用多模态后端。
3. `RuleJudge`：对选择题和 Yes/No 任务进行确定性规则判断。
4. `NLIJudge`：本地 DeBERTa 前提-假设蕴含判断，仅用于 Semantic Entropy 的语义聚类。

正式第一阶段的多模态 Judge 使用 `ClosedSourceJudge`，入口为 `scripts/judging/judge_responses.py`。它只处理 greedy 主回答：最终答案用于正确性，视觉观察和推理用于幻觉评分；幻觉布尔值由 `rating < 3` 确定性派生。无法分离 XML 三段的回答不调用 API，而记录 `judge.valid=false`。Judge JSONL 支持断点续跑，运行配置、模型、生成输入和 Prompt 版本任一变化都会拒绝续写。

VAUQ 和 VL-Uncertainty 的保留复现脚本通过 `src.llm_judge.OpenSourceJudge` 或 `RuleJudge` 调用统一实现，不再保留旧 Judge 类名或各自的重复解析器。

## 7. 指标与分析

指标入口为 `scripts/evaluation/compute_metrics.py`，按 `sample_id` 合并同一模型和数据集的生成、UQ 与 Judge 结果，计算错误检测和幻觉检测的 AUROC、AUPRC、PRR、ECE 及分组 bootstrap 置信区间。

分析入口为 `scripts/analysis/analyze_phase1_results.py`，读取 `results/generation/`、`results/uq/`、`results/judging/` 和 `results/metrics/`，生成 `results/analysis/phase1_uq/` 下的报告、CSV 和图表。当前分析只覆盖 3 × 3 第一阶段矩阵，不包含改进方法子集或第二阶段评测。

低不确定性幻觉（LUH）子集提取由 `scripts/analysis/` 下的脚本完成：`compute_common_luh.py` 在每个 dataset × model × method 单元格内做 average-rank percentile 归一化（默认低 UQ 阈值 0.25），输出跨至少两个模型的 common LUH 与三个模型一致的 core LUH；`extract_per_model_subset.py` 为每个模型独立提取 400 样本子集（200 条低不确定性幻觉正例 + 200 条三维 baseline 百分位最近邻匹配的非幻觉负例），使三种 baseline 在该子集上的 AUROC 接近 0.5；`extract_luh_subset.py` 是跨模型公共交集策略的早期版本。产物写入 `results/analysis/luh/`，提取定义与验证结果见 `docs/低不确定性子集提取说明.md`。

## 8. LoRA 工程

LoRA 训练代码位于 `LoRA/src/`，训练入口为 `LoRA/scripts/train_multimodal_lora.py`。训练目标是固定单行 XML：

```xml
<vision>视觉证据</vision><reasoning>简短推理</reasoning><answer>最终答案</answer>
```

正式数据为 5,000 条 VQAv2 XML 数据（4,000 train / 1,000 validation），三个模型分别训练独立 adapter。正式 adapter 位于 `results/lora/vqav2_5000_4to1/`，训练配置、loss、processor 和 adapter 权重与其一起保存。训练使用 rank 8、alpha 16、dropout 0.05、micro batch 1、梯度累积 16、1 epoch；具体模型差异和验证结果见 `LoRA/README.md`。

教师数据生成从 `prompts/LoRA/teacher_prompt.md` 和 `prompts/LoRA/few_shot_examples.json` 读取，并在样本记录中保存 Prompt 哈希。训练模块从版本化 XML Prompt 文件读取指令，不在 Python 代码中保留第二份文本副本。
