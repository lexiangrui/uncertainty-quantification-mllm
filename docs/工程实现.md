# 多模态大模型不确定性量化工程实现

本文档只描述当前仓库已经保留并完成的第一阶段工程，不包含已删除的实验路线或尚未实现的第二阶段方法评测。

## 1. 当前实验范围

第一阶段覆盖 3 个模型、3 个数据集、3 种 UQ 方法：

| 类别 | 当前配置 |
| --- | --- |
| 模型 | LLaVA-1.5-7B、Qwen2.5-VL-7B-Instruct、InternVL3.5-8B-HF |
| 数据集 | ViLP、HallusionBench、MM-Vet |
| UQ | Perplexity、Semantic Entropy、UMPIRE |
| 回答 | 1 条 greedy 主回答 + 10 条随机采样回答；每条 sample 最多 50 次 XML 拒绝重采样 |
| Judge | 闭源 Judge、开源 Qwen Judge、规则 Judge；Semantic Entropy 使用 NLI Judge |

采样数固定为 K=10，结果不再按 K 创建目录层级。当前 3 × 3 的 LoRA、生成、UQ、Judge、指标与分析已经写入下述统一路径；greedy 与 Judge 复用原第一阶段标签，samples、hidden 和 UQ 为 K=10 结果。

## 4. 生成流水线

入口为 `scripts/generation/generate_responses.py`，Slurm 模板为 `slurm/generation/generate_responses.sbatch`。每个模型均要求显式提供基础模型目录和对应 adapter：

```bash
python3 scripts/generation/generate_responses.py \
  --dataset vilp \
  --dataset-source /opt/lexiangrui/datasets/vilp/ViLP.parquet \
  --model-family llava_1_5 \
  --model-path /opt/lexiangrui/models/llava-1.5-7b-hf \
  --adapter-path results/lora/llava/adapter \
  --output results/generation/llava/greedy/vilp.jsonl \
  --phase greedy \
  --num-samples 0
```

生成器将数据转换为统一的 `BenchmarkSample`。`greedy` 阶段只写一条主回答，`samples`
阶段固定写 10 条随机采样回答、每条最多尝试 50 次 XML 拒绝重采样；两阶段互不读取对方文件。每条回答保存原始文本、XML 三段
解析结果、格式状态和采样元数据；samples 阶段还将每个采样答案末 token 的最后一层向量
写入 `results/hidden/<model>/<dataset>/` sidecar。运行记录保存模型、数据集、生成参数、Prompt 版本和全局 seed。

解析器要求 `<vision>`、`<reasoning>`、`<answer>` 各出现一次、顺序固定、内容非空且标签外无文本。解析失败时保留原始回答并标记无效，不猜测、不自动修复。

生成结果支持按 `sample_id` 断点续跑。已有输出的运行配置不一致时直接拒绝继续写入。模型只在存在未完成样本时加载；完全完成的运行不会重复加载权重。

网格作业入口为 `slurm/generation/submit_generation_grid.sh`，必须显式设置
`GENERATION_PHASE=greedy` 或 `GENERATION_PHASE=samples`，一次只提交一个阶段。

## 5. UQ 流程

UQ 独立入口为 `scripts/uq/compute_uq.py`，Slurm 模板为 `slurm/generation/compute_uq.sbatch`。
它显式读取 `--greedy-input` 与 `--sample-input`，输出统一的 UQ JSONL：

- Perplexity：greedy 最终答案 token 的 mean NLL 与 PPL；
- Semantic Entropy：对 samples 最终答案进行严格双向 NLI 聚类后计算语义熵；
- UMPIRE：使用 samples 最终答案末 token 的末层 hidden vector 计算不一致度。

greedy 阶段不提取 hidden。samples 阶段不保存完整 logits、完整 hidden states 或 KV cache，
只保存 UMPIRE 需要的最终答案末 token 末层 float16 向量。Perplexity 只读取 greedy；
Semantic Entropy 和 UMPIRE 只读取 samples。UQ 计算中的 DeBERTa NLI 模型通过 `NLIJudge`
加载，不再由 Semantic Entropy 维护独立 entailment 类。UQ 仅支持 answer-only；旧 combined
JSONL、完整 XML、外置 hidden manifest 和后处理 hidden 提取均不受支持。
3 × 3 UQ 网格由 `slurm/generation/submit_uq_grid.sh` 独立提交，只读取上述正式路径。

## 6. Judge 流程

统一 Judge 位于 `src/llm_judge/`，对外保留以下类别：

1. `ClosedSourceJudge`：通过 OpenAI SDK Responses API 调用闭源/托管模型；Prompt 来自 `prompts/judge/`。
2. `OpenSourceJudge`：通过模型名称切换 Qwen 后端。`Qwen2.5-3B-Instruct` 和 `Qwen3-4B-Instruct-2507` 使用文本后端，`Qwen3.6-VL` 使用多模态后端。
3. `RuleJudge`：对选择题和 Yes/No 任务进行确定性规则判断。
4. `NLIJudge`：本地 DeBERTa 前提-假设蕴含判断，仅用于 Semantic Entropy 的语义聚类。

正式第一阶段的多模态 Judge 使用 `ClosedSourceJudge`，入口为 `scripts/judging/judge_responses.py`。它只处理 greedy 主回答：最终答案用于正确性，视觉观察和推理用于幻觉评分；幻觉布尔值由 `rating < 3` 确定性派生。无法分离 XML 三段的回答不调用 API，而记录 `judge.valid=false`。Judge JSONL 支持断点续跑，运行配置、模型、生成输入和 Prompt 版本任一变化都会拒绝续写。

VAUQ 和 VL-Uncertainty 的保留复现脚本通过 `src.llm_judge.OpenSourceJudge` 或 `RuleJudge` 调用统一实现，不再保留旧 Judge 类名或各自的重复解析器。

## 7. 指标与分析

指标入口为 `scripts/evaluation/compute_metrics.py`，按 `sample_id` 合并同一模型和数据集的生成、UQ 与 Judge 结果，计算错误检测和幻觉检测的 AUROC、AUPRC、PRR、ECE 及分组 bootstrap 置信区间。

低不确定性幻觉（LUH）子集提取由 `scripts/extract_per_model_subset.py` 完成：为每个模型独立提取 400 样本子集（200 条低不确定性幻觉正例 + 200 条三维 baseline 百分位最近邻匹配的非幻觉负例，排除 `has_image=False` 的无图样本），使三种 baseline 在该子集上的 AUROC 接近 0.5。产物写入 `results/analysis/luh/`，提取定义与验证结果见 `docs/低不确定性子集提取说明.md`。

实验一结果分析由 `scripts/analysis/` 下三个模块完成：`a_descriptive.py` 输出有效性流转、标签统计、UQ 分数分布与采样语义一致性；`b_detection.py` 复用 `src/evaluation/metrics.py` 计算错误/幻觉检测的 AUROC、AUPRC、PRR、ECE 及方法差、目标差、ECE 分箱、风险覆盖与 C×H 子群分解，点估计与 `results/metrics/` 逐值一致；`c1_luh_profile.py` 在 LUH 困难子集上做规模量化、信号源归因（PPL 长度、SE 簇收敛、UMPIRE 分量）与特征画像。产物位于 `results/analysis/{descriptive,detection,luh_profile}/`，方案与字段审计见 `docs/实验一结果分析.md`。

## 8. LoRA 工程

LoRA 训练代码位于 `LoRA/src/`，训练入口为 `LoRA/scripts/train_multimodal_lora.py`。训练目标是固定单行 XML：

```xml
<vision>视觉证据</vision><reasoning>简短推理</reasoning><answer>最终答案</answer>
```

正式数据为 5,000 条 VQAv2 XML 数据（4,000 train / 1,000 validation），三个模型分别训练独立 adapter。正式 adapter 位于 `results/lora/<mllm>/adapter/`，训练配置、loss、processor 和 adapter 权重与其一起保存。训练使用 rank 8、alpha 16、dropout 0.05、micro batch 1、梯度累积 16、1 epoch；具体模型差异和验证结果见 `LoRA/README.md`。

教师数据生成从 `prompts/LoRA/teacher_prompt.md` 和 `prompts/LoRA/few_shot_examples.json` 读取，并在样本记录中保存 Prompt 哈希。训练模块从版本化 XML Prompt 文件读取指令，不在 Python 代码中保留第二份文本副本。
