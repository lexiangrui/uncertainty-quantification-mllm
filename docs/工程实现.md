# 多模态大模型不确定性量化工程实现

## 1. 工程目标

本项目面向多模态大模型的不确定性量化与高置信度幻觉检测，整体分为两个相互衔接的实验阶段。

### 1.1 方法专属低不确定性幻觉子集提取

在 ViLP、HallusionBench 和 MM-Vet 等数据集上运行多个被测多模态大模型，生成 greedy 主回答和不确定性量化所需的随机采样回答。使用 `baseline/` 中复现的不确定性量化方法计算分数，并通过统一 LLM Judge 生成正确性与幻觉标签。

对每个“被测模型 × UQ 方法”组合，直接按该方法的原始分数提取 200 条最低不确定性幻觉（LUH）作为正类，再从同一组合的非幻觉候选池中提取原始分数最低的 200 条作为低不确定性非幻觉负类，形成可版本化、可复现的方法专属评测子集。负类只用于二分类评价，不作为高不确定性非幻觉研究对象。

### 1.2 改进不确定性量化方法评测

将后续新增的改进方法分别应用到九个方法专属子集，以 LUH 为正类、低不确定性非幻觉为负类，与定义该子集的 baseline 及其他方法比较 AUROC/AUPRC。每项结果必须同时标注被测模型和用于定义 LUH 的 UQ 方法。

两个阶段共用数据适配、模型加载、回答生成、LLM Judge、评估指标和通用工具等基础设施，但各个不确定性量化方法仍保持独立工程目录。

---

## 2. 总体设计原则

1. **公共能力与方法实现分离**

   `src/` 只保存多个实验和方法都需要的公共能力，不在其中实现具体的不确定性量化方法。

2. **每个 UQ 方法保持独立**

   `baseline/` 中的复现方法以及后续新增的改进方法保持各自的目录和内部实现，暂不强制统一内部结构。

3. **数据和权重不进入仓库**

   数据集、模型权重和大型中间产物保存在服务器上。仓库只通过配置文件或环境变量引用服务器绝对路径，不设置本地 `data/` 目录。

4. **统一数据协议**

   数据集适配器、模型适配器、UQ 方法和评估模块之间使用统一的样本标识和输出字段，保证不同方法的结果能够稳定合并。

5. **生成与模型内 UQ 共用一次模型生命周期**

   greedy 主回答与随机采样回答仍作为可复用实验产物保存。需要被测模型内部信号的方法在每题回答刚生成完、模型尚未释放时立即计算，只保存最终分数和必要审计摘要，不持久化 token logits、hidden states、attention、KV cache 或梯度。Judge 与不依赖被测模型的评估保持独立后处理。

6. **实验产物可追溯**

   每项结果应当能追溯到数据集版本、模型标识、Prompt 版本、生成参数、UQ 方法配置和 Judge 版本。

## 4. 目录职责

### 4.1 `docs/`

保存项目总体设计、实验方案、工程实现、子集说明、阶段汇报和论文阅读笔记。原 `LU Hallucination Bench/` 中的实验设计文档后续可归入该目录，但本文档不执行实际迁移。

### 4.2 `configs/`

保存公共实验配置，包括实验阶段、数据集、模型、Judge 和 UQ 方法参数。

配置中应使用环境变量或服务器路径指定：

- Hugging Face 数据集缓存路径；
- 数据集预处理结果路径；
- 模型权重路径；
- 大型中间产物与子集输出路径。

不应在配置中提交 API Key、密码或其他敏感信息。

### 4.3 `prompts/`

保存被测模型的结构化回答 Prompt 和 LLM Judge Prompt。Prompt 应当独立版本化，修改 Prompt 时不覆盖已完成实验所使用的版本。

### 4.4 `src/`

`src/` 只保留以下六类公共能力。

#### `datasets/`

将 ViLP、HallusionBench 和 MM-Vet 等数据集转换为统一样本协议，处理数据集 split、图像输入、GT、原始问题 ID 和元数据差异。

ViLP 的三个 QIA 实例需要具有独立样本 ID，同时保留共享的原始问题分组 ID，以支持分组统计和 cluster bootstrap。

#### `models/`

封装 LLaVA-1.5、Qwen2.5-VL 和 InternVL3.5 的加载、LoRA adapter 挂载、多模态输入构造和回答生成接口。生成调用可以在内存中向 UQ 方法提供概率等瞬时信号，但公共结果协议不保存内部状态。

具体 UQ 方法不在此目录实现；该目录只为各方法提供统一模型访问能力。

#### `generation/`

负责生成和解析结构化回答，包括：

- greedy 主回答；
- \(K=10\) 次随机采样回答；
- 单行 `<vision><reasoning><answer>` XML 三部分的严格解析；
- 生成参数、Prompt 版本和每次采样随机种记录；
- JSONL 结果写入与按完整样本断点续跑。

#### `llm_judge/`

作为项目统一 Judge 实现，后续承接现有 `judge/` 的能力。该目录负责 Judge 请求构造、多模态输入、结构化输出解析、重试、缓存和错误记录。

正确性与幻觉是两个独立标签：

- 正确性只评价解析后的最终答案与 GT 的一致性；
- 幻觉只评价视觉观察与推理部分中是否存在无支持内容。

Judge 不属于当前回答生成阶段，本阶段不调用该模块。

#### `evaluation/`

负责两个实验阶段的统一评估，包括：

- Accuracy 与 Hallucination Rate；
- UQ 检测性能指标；
- 分组统计与 bootstrap 置信区间；
- 高置信度幻觉子集选择；
- 子集规模、类型和模型来源统计；
- baseline 与改进方法的统一比较；
- 表格、图表和汇总报告生成。

子集提取属于评估和结果筛选环节，因此不再单独设置 `extraction/` 目录。

#### `utils/`

保存配置读取、统一数据结构、JSONL/JSON 读写、日志、随机种、分布式运行和结果完整性检查等通用功能。

### 4.5 `scripts/`

保存实验命令入口，负责解析参数、调用公共模块和组织单个实验阶段。核心数据处理、Judge 和评估逻辑不应直接堆放在脚本中。

不再设置 `pipelines/` 目录；需要串联多个阶段时，由入口脚本、Slurm 依赖关系或外部调度完成。

### 4.6 独立 UQ 方法目录

`baseline/` 保存已复现的不确定性量化方法，用于子集提取和后续对比评测。

后续新增的改进方法原则上建立一个独立的一级目录。

公共工程层对 UQ 方法只约定最小输入输出协议，不要求各方法立即重构为相同的内部目录。

### 4.7 `LoRA/`

`LoRA/` 是用于修复三个被测模型结构化回答指令遵循的独立微调工程，不并入 UQ 方法目录。训练目标固定为不含换行的单行 XML：

```xml
<vision>视觉证据</vision><reasoning>简短推理</reasoning><answer>最终答案</answer>
```

初始训练集使用 VQAv2 train2014 的 2,000 条样本，按 `image_id` 隔离为 1,600 条训练、200 条验证和 200 条留出格式测试数据。ViLP、HallusionBench 和 MM-Vet 不用于微调，避免评测泄漏。

数据构造分为四步：

1. 从 VQAv2 官方问题与标注中筛选人类答案一致度不低于 7/10 的样本；
2. 将真实图像、问题和多数答案发送给兼容 OpenAI Chat Completions 的 `qwen3.7-plus`；
3. 教师模型只生成 `vision`、`reasoning`、`answer` 三个 JSON 字段；本地代码校验最终答案、长度、字段和禁止内容；
4. 由本地程序转义文本并确定性封装 XML，拒绝用机械模板兜底失败样本。

API 地址和密钥分别由 `QWEN_TEACHER_BASE_URL`、`QWEN_TEACHER_API_KEY` 注入，仓库模板保持为空，生成结果不记录二者。教师生成采用按样本追加 JSONL 和 `question_id` 断点续跑。

三个模型分别训练独立 adapter，统一采用 rank 8、alpha 16、dropout 0.05，仅注入语言模型的 `q_proj` 和 `v_proj`。视觉塔、多模态投影层及全部原始参数冻结，micro batch 为 1、梯度累积为 16、训练 1 epoch、学习率为 `2e-4`。监督 loss 只覆盖 assistant XML 及官方 end-of-turn token。LLaVA 使用 FP16，Qwen2.5 与 InternVL3.5 使用 BF16；InternVL3.5 因视觉 token 较多，序列上限为 4096，其余两者为 1024。

数据和模型仍位于 `/opt/lexiangrui/`；生成数据准备在联网的登录或调试节点完成。Slurm `debug01` 计算节点启用 Hugging Face 离线变量，仅从本地权重训练；checkpoint 和日志写入 `/home/lexiangrui/results/lora/`。具体命令和校验规则见 `LoRA/README.md`。

### 4.8 `tests/`

用于测试公共工程能力和两条实验主链路。每个 UQ 方法特有的单元测试可继续保留在方法自己的目录中。

### 4.9 `slurm/`

统一管理服务器上的作业脚本。`subset_extraction/` 对应第一阶段，`subset_evaluation/` 对应第二阶段；各 UQ 方法仍可保留独立的 Slurm 目录。

### 4.10 `results/` 与 `logs/`

`results/` 在逻辑上分为子集提取结果和子集评测结果。`logs/` 按实验阶段和方法存放 Slurm 输出及运行日志。

仓库中仅建议保留小型汇总结果、最终统计表和可读报告。大型原始回答、隐藏状态、token logits、模型缓存及完整子集应存放在服务器路径中。

## 5. 数据流与两阶段关系

```text
服务器数据集
    ↓
datasets
    ↓
models + generation
    ↓
主回答 + 采样回答
    ├──→ baseline
    └──→ llm_judge
             ↓
         evaluation
             ↓
   方法专属 LUH + 低不确定性非幻觉子集
       ├──→ baseline
       └──→ 改进方法
                ↓
            evaluation
```

### 5.1 第一阶段：子集提取

1. 从服务器读取完整数据集；
2. 将数据样本转换为统一格式；
3. 使用被测模型生成 greedy 主回答；
4. 为需要多次采样的 UQ 方法生成共享采样回答；
5. 使用 baseline UQ 方法计算不确定性分数；
6. 使用 LLM Judge 对主回答生成正确性和幻觉标签；
7. 按样本 ID 和模型 ID 合并生成、UQ 与 Judge 结果；
8. 按“模型 × UQ 方法”分别以原始分数排序，提取 200 条最低分幻觉和 200 条最低分非幻觉（每组合 200 + 200）；
9. 输出子集元数据、版本信息和统计报告。

### 5.2 第二阶段：改进方法子集评测

1. 从服务器读取固定版本的方法专属 LUH 与低不确定性非幻觉子集；
2. 在相同样本和模型设置上运行 baseline 及后续改进方法；
3. 将各方法输出转换为统一评估格式；
4. 按“模型 × 子集定义方法”分别计算以 LUH 为正类、低不确定性非幻觉为负类的 AUROC/AUPRC 与置信区间；
5. 按数据集、模型、幻觉类型和样本属性进行分组分析；
6. 生成 baseline 与改进方法的对比报告。

## 6. 统一中间数据协议

为了避免强制重构各 UQ 方法，公共工程层只规定最小交换协议。

### 6.1 样本记录

每个数据集样本至少包含：

- `sample_id`：全局稳定的问题实例 ID；
- `group_id`：原始问题或问题组 ID；
- `dataset`、`split`：数据集和分割标识；
- `question`：官方问题；
- `references`：一个或多个 GT；
- `image_ref`：服务器图像引用或空值；
- `metadata`：数据集特有属性。

### 6.2 生成记录

每条主回答或采样回答至少包含：

- `sample_id` 与 `model_id`；
- 原始完整回答；
- 解析后的 vision、reasoning 和 answer；
- 生成模式与采样序号；
- 生成参数和随机种；
- Prompt 版本；
- 解析状态和错误信息。

### 6.3 UQ 结果

每种方法至少输出：

- `sample_id` 与 `model_id`；
- `method_id` 与方法版本；
- 主不确定性分数；
- 可选的分项分数与调试信息；
- 方法配置哈希；
- 运行状态。

所有用于统一比较的主分数必须满足：数值越高表示不确定性越高。如果某方法的原始定义相反，应在输出适配层进行方向转换，同时保留原始分数。

### 6.4 Judge 结果

每条 Judge 记录至少包含：

- `sample_id` 与 `model_id`；
- `correct`；
- `hallucination`；
- 0–6 幻觉评分；
- 幻觉类型；
- 简短判定理由；
- Judge 模型与 Prompt 版本；
- 原始 Judge 输出和解析状态。

### 6.5 子集记录

方法专属 LUH 子集不应只保存一组样本 ID，还应保存：

- 子集版本；
- 来源数据集和被测模型；
- 选择所使用的 UQ 方法；
- 原始分数方向、LUH cutoff 与负样本随机种子；
- Judge 版本；
- 选择原因和对应分数；
- 原始样本的服务器引用；
- 可复现子集的配置信息。

## 7. 方法专属低不确定性幻觉子集定义

**所有分析按“模型 × UQ 方法”独立进行**：三个数据集在同一组合内合并；共 9 个组合，不跨模型或方法合并原始分数。

对模型 \(a\) 和方法 \(m\) 的有效候选池 \(E_{a,m}\)，直接使用该方法的原始不确定性分数 \(s_{i,m}\)，不计算百分位、统一分数或跨方法一致性秩。将 \(H=1\) 记录按 \((s_{i,m},\texttt{sample\_id})\) 升序排序，提取前 \(k=200\) 条：

\[
S_{\mathrm{LUH}}^{a,m}
=\operatorname{TopK}_{\min s_{i,m}}
\{i\in E_{a,m}:H_i=1\}.
\]

再从同一候选池的 \(H=0\) 记录中，按同一方法原始分数升序取前 \(k=200\) 条：

\[
S_{\mathrm{LUN}}^{a,m}
=\operatorname{TopK}_{\min s_{i,m}}
\{i\in E_{a,m}:H_i=0\}.
\]

每个组合共 400 条，九个组合共 3,600 条方法专属成员关系。同一样本可以属于多个方法子集，因此交换协议采用包含 `uq_method` 和 `subset_label` 的长表。低不确定性非幻觉负类要求 \(H=0\)，并且在同一方法候选池中取原始分数最低的 200 条；它不定义为 HUN。完整定义见实验设计文档 §8。

阈值应在查看改进方法结果之前确定，避免根据改进方法的表现反向调整子集，导致评估泄漏。

## 8. 服务器存储约定

由于数据集和模型权重均位于服务器，建议将路径分为以下逻辑类型：

- 数据集原始缓存；
- 统一格式的数据索引；
- 模型权重；
- 主回答与采样回答；
- UQ 中间产物；
- Judge 缓存；
- 版本化子集；
- 方法对比结果。

路径通过命令行参数传入生成程序。当前服务器上已经确认的资产路径为：

## 9. 实验运行与断点续跑

每个高成本阶段应支持独立运行和断点续跑，不应将完整实验绑定为一个不可恢复的长任务。

建议的阶段边界为：

1. 数据集检查与统一索引构建；
2. greedy 主回答生成；
3. 随机回答采样；
4. baseline UQ 分数计算；
5. LLM Judge；
6. 结果合并与子集提取；
7. 改进方法子集评测；
8. 汇总统计与报告生成。

每个阶段启动时应先检查已有输出，默认跳过经验证完整的记录，对失败或不完整记录重新计算。

## 10. 当前已实现：通用回答生成流水线

### 10.1 实现范围

当前代码完成以下最小闭环：

1. 从显式服务器路径离线读取 ViLP、HallusionBench 和 MM-Vet；
2. 将官方数据转换为统一 `BenchmarkSample`；
3. 从本地权重加载 LLaVA-1.5-7B、Qwen2.5-VL-7B-Instruct 或 InternVL3.5-8B-HF，并挂载各自正式 LoRA adapter；
4. 对每条问题生成一条 greedy 主回答；
5. 以 `temperature=1.0` 逐次生成十条共享采样回答，不传入 `top_p` 或 `top_k`；
6. 严格提取单行 XML 中的视觉观察、推理和答案三个部分，不修改原始回答；
7. 每个样本完整生成十一条回答后，以一条 JSONL 记录写入输出；
8. 根据 `sample_id` 断点续跑；若已有文件的运行配置与当前命令不一致则直接失败。

模型权重采用延迟加载：程序先读取已有 JSONL 并检查运行配置与已完成样本；只有遇到首条尚未完成的样本时才加载 processor 和模型。因此完全完成的任务再次提交时不会重复读取权重。

当前已在同一生成作业中接入 Perplexity、Semantic Entropy 和 UMPIRE。LLM Judge 已实现为生成后独立入口；按模型、按方法独立提取 LUH 与低不确定性非幻觉负类的脚本和单元测试已实现。

公开生成入口固定每题采样十次，不提供修改 K 的命令行参数。入口强制提供 `--adapter-path`，避免将 base 权重与格式微调后模型的结果混用。Qwen2.5 和 InternVL3.5 显式关闭模型原生 thinking 模板。

回答生成启用 `return_dict_in_generate` 和 `output_logits`，逐步从 temperature/top-k/top-p 等采样处理前的原始 logits 计算实际生成 token 的 log probability。实现不堆叠并保存完整词表 logits，而是逐生成步提取命中 token 的标量概率；解析出最终答案 token 区间后，只在内存中计算 sequence/mean log probability。生成时还通过最后一层语言模型 forward hook 仅捕获当前回答最终 token 的 hidden vector。每题十条采样完成后，概率和向量立即交给三个 UQ 方法，形成标量结果后释放。

运行协议固定为 `online-before-model-release-v1`。JSONL 不再写入 `generation_trace`、`answer_trace`、token ID、token log probability、response embedding 或其他模型内部状态。未来改进方法也应在同一模型生命周期中自行提取所需瞬时信号、立即形成分数并释放临时张量，不扩展成“保存全部内部状态”的通用 `.pt` 协议。

### 10.3 Prompt 与回答组织

三个模型使用实验设计中的同一份单行 XML Prompt。回答任务、输出要求、官方图像与官方问题均放入同一条 user message，不创建 system message。格式固定为：

```text
<vision>...</vision><reasoning>...</reasoning><answer>...</answer>
```

解析器要求三个标签各出现一次、顺序固定、内容非空且标签外无文本。解析失败时不猜测、不补写也不重试；原始输出仍被保存，`sections_valid=false`，并记录错误原因。

### 10.4 JSONL 记录

一条 JSONL 对应一个“问题实例—模型”组合，包含：

- `run`：数据路径、模型路径、模型族、模型运行配置、Prompt 版本、生成参数和全局 seed；
- `sample`：样本 ID、分组 ID、数据集、split、问题、GT、是否含图像和元数据；
- `greedy`：原始主回答、三部分可分性、解析错误和提取后的三个部分；
- `samples`：十条随机回答、序号、独立稳定 seed、三部分可分性和提取后的三个部分。
- `uq`：同题回答完成后在线计算的不确定性结果；当前包含 Perplexity、Semantic Entropy 和 UMPIRE 的分数及必要审计标量。

图像像素不写入 JSONL；后续阶段通过稳定样本 ID 回到相同数据源读取图像。

### 10.8 Semantic Entropy 工作流

`baseline/semantic_uncertainty_repro/` 已从独立复现工程收敛为统一生成流水线中的在线方法。旧的数据集适配、被测模型后端、回答生成、正确性 Judge、指标汇总、下载脚本、独立 JSONL runner 和文本 QA 支持均已移除；方法目录只保留本地 DeBERTa 蕴含模型、严格双向蕴含聚类和语义熵计算。

对每题的固定十条采样最终答案，令第 \(i\) 条答案的长度归一化 log probability 为

\[
\ell_i=\frac{1}{|y_i|}\sum_j\log p_M(w_{i,j}\mid q,w_{i,<j}).
\]

先在十条已观察回答之间归一化

\[
\tilde p_i=\frac{\exp(\ell_i)}{\sum_k\exp(\ell_k)},
\]

再对严格双向蕴含得到的语义簇聚合 \(p(c)=\sum_{i:y_i\in c}\tilde p_i\)，最终输出

\[
\operatorname{SE}(q)=-\sum_c p(c)\log p(c).
\]

采用 mean log probability 是为了避免不同回答长度直接主导有限样本概率质量；run 中将该口径固定为 `answer_mean_log_prob_from_transient_raw_logits`，不能与纯采样频率熵或未归一化序列概率混称。任一采样回答无法分段时，该题在同一生成记录的 `uq.semantic_entropy` 中标为无效，不退化为另一种估计量。

回答生成入口为 `scripts/generation/generate_responses.py`，Slurm 入口为 `slurm/generation/generate_responses.sbatch`。该阶段只保存 JSONL 回答、概率统计和 `.pt` hidden-state sidecar，不加载 DeBERTa。独立 UQ 入口为 `scripts/uq/compute_uq.py`，Slurm 入口为 `slurm/generation/compute_uq.sbatch`；该阶段才加载 DeBERTa，并输出 Perplexity、Semantic Entropy 和 UMPIRE 结果。默认将 DeBERTa 放在 CPU；若设置 `ENTAILMENT_DEVICE=cuda`，UQ 作业必须显式申请 GPU。

新的在线、不落内部状态流水线已在 Slurm 作业 `106806` 完成 LLaVA-1.5 × ViLP 单样本验证：1 条 greedy 与 10 条采样回答均可分段，Semantic Entropy 有效且为 `1.7679653195`；十条答案被分为 8 个语义簇，三条“四个螺旋桨”回答聚入同一簇，簇概率约为 `0.439867`。输出 JSONL 递归检查未发现 `generation_trace`、`answer_trace`、token ID、token log probability、logits 或 hidden states。该结果与旧分阶段算法结果一致，说明执行时机和存储协议调整没有改变当前语义熵数值。

### 10.9 Perplexity 与 UMPIRE 工作流

`baseline/perplexity_repro/` 实现实验设计中的单回答概率基线。它对 greedy 最终答案区间计算 mean NLL 与 `exp(mean_nll)`。该值直接来自生成该 token 序列时的自回归条件分布，与固定同一序列的 teacher forcing 计算数学等价，因而不增加一次前向。输出只保存 `score`、`mean_nll` 和答案 token 数。

`baseline/umpire_repro/` 依据 [UMPIRE 论文 arXiv:2602.24195v1](https://arxiv.org/abs/2602.24195) 与[作者官方仓库](https://github.com/daohieu17ctt/UMPIRE)实现。每条采样回答使用最后一层语言模型对最终回答 token 的 hidden vector，L2 归一化后组成 Gram 矩阵；jitter 按官方入口取 `1e-8`。官方包装器通过 `compute_transition_scores(..., normalize_logits=True)` 使用实际生成 scores，因此不一致度采用 temperature 等生成处理后的最终答案联合概率，不使用长度归一化概率；PPL 与当前 Semantic Entropy 仍使用处理前原始模型 logits。两套标量都只在内存中存在。

论文将分数写为按采样数归一化的语义体积与平均不一致度之和；作者官方代码实际以未归一化 `logdet + alpha * sum(1-p_i)` 作为正式输出，并以无标签数据上 `abs(median(logdet) / median(sum(1-p_i)))` 确定自适应 alpha。本工程的 `score` 严格对齐官方代码，同时保存论文口径的 `semantic_volume` 与 `incoherence_mean` 以及官方口径的两个标量分量。一次运行结束后仅从这些标量确定 alpha 并原子回写 JSONL；回答 embedding 和 token probability 不会落盘。

自适应 alpha 必须在完整的无标签“模型 × 数据集”运行内估计。`--limit` 仅用于工程 smoke；若只有一个样本，alpha 按定义会把该样本的两个分量平衡，使最终分数约为零，因此限量结果不能进入正式排序或指标计算。

当前正式 prompt 会生成视觉观察、推理和最终答案三部分。论文允许对长推理回答限制到 final answer span，本工程因此将 PPL、Semantic Entropy 和 UMPIRE 的概率信号统一限定为最终答案区间；UMPIRE 向量取最终回答 token，而不是整段推理的均值池化。

当前本地整理后的生成、Judge、三个 UQ 方法和 LoRA 核心回归测试共 `56` 项，全部通过。一次性 smoke 脚本、旧 Prompt 分支、测试 adapter 与日志已从本地和服务器清理；正式结果与 loss 数据不依赖 Slurm 文本日志。
