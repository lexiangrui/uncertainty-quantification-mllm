# 多模态大模型不确定性量化工程实现

本文档描述当前仓库的正式工程路径与可用入口。

## 1. 实验配置

| 类别 | 当前配置 |
| --- | --- |
| 模型 | LLaVA-1.5-7B、Qwen2.5-VL-7B-Instruct、InternVL3.5-8B |
| 数据集 | ViLP、HallusionBench、MM-Vet |
| 回答 | 1 条 greedy + 10 条 samples；每条 sample 最多 50 次 XML 拒绝重采样 |
| UQ | Perplexity、Semantic Entropy、UMPIRE |
| Judge | 闭源 Judge、开源 Qwen Judge、规则 Judge；Semantic Entropy 使用 NLI Judge |
| 改进方法 | ERA（Early Rationale Attribution） |

采样数固定为 K=10，结果使用统一的固定目录结构。数据集、模型权重、API 凭据和正式结果不提交到 Git。

## 2. 模块职责

```text
prompts/                      版本化生成、LoRA 和 Judge Prompt
src/datasets/                 三数据集统一为 BenchmarkSample
src/models/                   vLLM generation backend、HF replay backend、资源配置
src/generation/               XML Prompt、解析、调度和记录格式
src/llm_judge/                闭源、开源、规则与 NLI Judge
src/uq/                       分离 greedy/samples 的 UQ 调度
src/improvement/              ERA 输入对齐与注意力归因
baseline/                     三种正式 UQ 与保留论文复现
LoRA/                         XML 数据构造、训练和验证
scripts/                      各阶段命令行入口
slurm/                        集群正式入口
results/                      本地/集群运行产物（Git ignored）

```

Prompt 由文件加载并记录 SHA256：

- 正式生成与 LoRA 指令：`prompts/LoRA/xml_lora_instruction.md`
- 教师数据：`prompts/LoRA/teacher_prompt.md` 与 `prompts/LoRA/few_shot_examples.json`
- 闭源 Judge：`prompts/judge/closed_source_judge.md`

## 3. vLLM + HF 正式生成流水线

正式入口是 `slurm/generation/generate.sbatch`，单个 Slurm 作业内按以下顺序执行：

1. `scripts/generation/run_vllm_pipeline.py` 创建一个 vLLM engine；
2. 同一 engine 依次处理 ViLP、HallusionBench、MM-Vet 的 greedy 与 samples；
3. vLLM JSONL 保存回答、解析状态、运行配置和精确生成 token sidecar；
4. vLLM 释放后，`scripts/generation/run_hf_replay_pipeline.py` 创建一个 HF replay backend；
5. 同一 HF 模型依次回放全部数据集和阶段的精确 token；
6. final JSONL 写入 HF 计算的答案概率信号，samples 另写最后答案 token 的末层 hidden sidecar。

因此，greedy 和 samples 不会分别加载模型；每个模型一次作业只有一次 vLLM 权重加载和一次 HF 权重加载。模型映射为：

| 模型键 | family | checkpoint | adapter |
| --- | --- | --- | --- |
| `llava` | `llava_1_5` | `$MODEL_ROOT/llava-1.5-7b-hf` | `results/lora/llava/adapter` |
| `qwen` | `qwen2_5_vl` | `$MODEL_ROOT/Qwen2.5-VL-7B-Instruct` | `results/lora/qwen/adapter` |
| `internvl` | `internvl3_5_original` | `$MODEL_ROOT/InternVL3_5-8B` | `results/lora/internvl/adapter-original` |

运行示例：

```bash
sbatch --export=ALL,MODEL=internvl slurm/generation/generate.sbatch
```

三模型 generation → UQ 的依赖作业由下列入口统一提交：

```bash
bash slurm/submit_full_pipeline.sh
```

### 3.1 产物分层

```text
results/generation/<model>/
  vllm_raw/
    greedy/<dataset>.jsonl
    greedy/<dataset>.tokens/*.pt
    samples/<dataset>.jsonl
    samples/<dataset>.tokens/*.pt
  greedy/<dataset>.jsonl
  greedy/<dataset>.tokens/*.pt
  samples/<dataset>.jsonl
  samples/<dataset>.tokens/*.pt

results/hidden/<model>/<dataset>/*.pt
```

`vllm_raw/` 是生成阶段的可复用边界。final `greedy/` 与 `samples/` 保持同样的生成文本/token，但其中 `signals` 来自 HF teacher forcing。samples 的 hidden sidecar 为 `[K, hidden_size]` 的 float16 tensor，每一行对应一条 sample 的最终答案末 token。

### 3.2 解析与异常样本

解析器要求 `<vision>`、`<reasoning>`、`<answer>` 各出现一次、顺序固定、内容非空且标签外无文本。格式失败时保留原始回答并写入错误原因，不猜测或自动修复。sample 会在新 seed 下最多拒绝重采样 50 次；仍失败的记录保留为无效样本，下游 UQ 会跳过。

### 3.3 显存与批处理

资源策略位于 `src/models/runtime.py`：

| 模型 family | vLLM `max_model_len` |
| --- | ---: |
| `qwen2_5_vl` | 18,000 |
| 其他正式 family | 4,096 |

Qwen2.5-VL 的 18,000 来自当前 processor 与完整数据集上界：最多 16,384 个视觉 token、155 个渲染文本 token 和 512 个生成 token，保守总上界为 17,050。

| 可见显存 | vLLM `max_num_seqs` | HF replay batch |
| ---: | ---: | ---: |
| `<20 GiB` | 2 | 1 |
| `20–<24 GiB` | 4 | 2 |
| `24–<30 GiB` | 6 | 4 |
| `30–<48 GiB` | 8 | 5 |
| `≥48 GiB` | 16 | 8 |

32 GiB 节点使用已经验证的 HF batch size 5。HF replay 捕获 `torch.OutOfMemoryError` 后将当前 batch 二分并重试，直到成功或单样本仍 OOM；生成后端始终为 vLLM。

### 3.4 HallusionBench 无图记录

HallusionBench 文件先包含 951 条有图记录，再包含 178 条无图记录。HF replay 先按 `has_image` 分组，再在同一模态内组 batch，避免 padding/processor 混合路径不一致。

对 InternVL3.5-8B 的无图记录：

- Prompt 不插入 `<image>`、`<img>` 或 `<IMG_CONTEXT>`；
- 不传 `pixel_values` 与 `image_flags`；
- replay forward 直接调用注入 LoRA 后的 `language_model`。

这样既不伪造视觉输入，也避免 InternVL3.5-8B 视觉 wrapper 在 `pixel_values=None` 时进入不适用的视觉前向。

## 4. 断点续跑与一致性

JSONL 第一条是 `record_type=run` 的完整运行头，后续记录按 `sample_id` 写入。`completed_sample_ids` 在续跑前严格比较整个 `run` 配置；不一致时抛出错误，不允许在同一文件中混写不同模型、Prompt、参数、数据源或上游产物。

各阶段可以独立恢复：

- vLLM raw：跳过已有 `sample_id`，要求其 token sidecar 仍存在；
- HF replay：读取完整 raw 记录，只为 final JSONL 中缺失的 `sample_id` 回放；
- UQ/Judge/ERA：按各自输出的 `sample_id` 恢复，并把上游 run metadata 纳入自身 run 配置。

若只修改 replay 兼容性，应保留 `vllm_raw/`，重做 final generation 及其下游。若修改模型、adapter、Prompt 或采样参数，则必须从受影响的 raw 阶段重做。作业以 `flock` 避免两个进程同时写同一模型/数据集。

## 5. UQ

入口为 `scripts/uq/compute_uq.py`，Slurm 模板为 `slurm/uq/compute_uq.sbatch`：

```bash
sbatch --export=ALL,MODEL=qwen slurm/uq/compute_uq.sbatch
```

它只接受分离的 final greedy/samples 文件：

- Perplexity：读取 greedy 最终答案的 HF `mean_log_prob`；
- Semantic Entropy：使用 samples 最终答案、HF `mean_log_prob` 和 DeBERTa 双向 NLI 聚类；
- UMPIRE：使用 samples 的 HF probability 与 hidden sidecar。

UQ 输入为分离的 final greedy/samples JSONL，量化对象固定为 `<answer>` 内容；samples 记录通过 `hidden_states` 描述符读取正式 float16 sidecar。格式无效或信号不完整的样本不会进入分数计算。

## 6. Judge、指标与分析

正式多模态 Judge 入口为 `scripts/judging/judge_responses.py`。它只处理 greedy：最终答案用于正确性，视觉观察与推理用于幻觉评分；`rating < 3` 确定性导出 hallucination。解析失败的回答不调用 API，而写入 `judge.valid=false`。

`scripts/evaluation/compute_metrics.py` 按 `sample_id` 合并 generation、UQ 与 Judge，计算错误检测/幻觉检测的 AUROC、AUPRC、PRR 和 group-level bootstrap 置信区间。

LUH 提取和实验一分析入口分别位于 `scripts/extract_per_model_subset.py` 与 `scripts/analysis/`。它们消费既有正式结果，不属于 generation → UQ 自动提交 DAG。

## 7. ERA

ERA 读取 final greedy JSONL 和其精确 token sidecar，使用 HF eager attention 对同一回答做一次前向，计算答案对图像、问题、视觉描述和推理区域的注意力质量。正式流程使用子集提取阶段生成的 `results/analysis/luh/<model>_subset_ids.txt`，每个模型只对其中 400 条样本执行 attention forward。正式 Slurm 入口：

```bash
sbatch --export=ALL,MODEL=llava slurm/improvement/run_era.sbatch
```

输出位于 `results/era_components/<model>/<dataset>.jsonl`。子集 ID 会写入输出 run metadata，防止全量与子集产物混合；已完成的目标样本会在加载模型前排除。无图、XML 无效、token sidecar 缺失或无法对齐的样本会被显式跳过。方法定义见 [ERA 方法说明](ERA早期推理归因不确定性量化方法.md)。

## 8. LoRA

正式训练数据为 5,000 条 VQAv2 XML 数据（4,000 train / 1,000 validation）。三个模型使用相同 rank 8、alpha 16、dropout 0.05、micro batch 1、梯度累积 16、1 epoch；视觉塔和原始模型参数冻结，仅语言模型 `q_proj` / `v_proj` 注入 LoRA。

LLaVA/Qwen adapter 使用 `results/lora/<model>/adapter/`；InternVL3.5-8B adapter 使用 `results/lora/internvl/adapter-original/`。详细配置见 [LoRA README](../LoRA/README.md)。

## 9. 测试

在项目依赖环境中运行：

```bash
pytest -q
```

当前测试覆盖三数据集适配、Prompt/解析、JSONL 一致性与恢复、vLLM 后端、HF replay、显存档位与 OOM 拆分、InternVL 无图 forward、三种 UQ、四类 Judge、LoRA 辅助逻辑和 ERA。
