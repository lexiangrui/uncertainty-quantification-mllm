\subsection{Dataset Details}

\textbf{ViLP.} The Hugging Face release contains 300 distinct questions, each paired with three images and answers: one prior-consistent answer and two test answers that require joint use of textual and visual evidence. Expanding all three pairings yields 900 QIA instances. Each QIA is evaluated independently, while grouped statistics and bootstrap resampling cluster by the original question identifier to avoid treating the three related instances as independent. The benchmark creates direct conflicts between language priors and visual evidence, as illustrated by Case~1 in \Cref{subsec:representative_cases}.

\textbf{HallusionBench.} HallusionBench contains 1,129 instances: 951 in the \texttt{image} split and 178 in the \texttt{non\_image} split. It covers Visual Dependent and Visual Supplement settings and includes figures, charts, maps, tables, OCR, illusions, mathematics, and video frames. Both splits are used in the full evaluation; instances with \texttt{visual\_input=0} receive no image and are excluded only when constructing the ERA difficult subsets, which require visual tokens.

\textbf{MM-Vet.} The \texttt{test} split contains 218 open-ended visual questions covering recognition, OCR, knowledge, spatial awareness, language generation, mathematics, and combinations such as OCR+math. Reference answers may be words, numbers, lists, short sentences, or descriptions. Correctness is judged semantically from the content inside \texttt{<answer>}.

\subsection{Prompt Templates}

\subsubsection{Response Instruction (\texttt{xml-lora-zero-shot-v1})}

The image, question, and response instruction are placed in one user message:

\begin{lstlisting}
[Image]
{official_image}

[Question]
{official_question}

[Response requirements]
Answer using exactly these three XML tags once and in order, with no line breaks
and no text outside them: <vision>relevant visible evidence</vision><reasoning>brief
reasoning</reasoning><answer>concise final answer</answer>
\end{lstlisting}

\subsubsection{Judge System Prompt (\texttt{closed-source-correctness-hallucination-v1})}

\begin{lstlisting}
You are an impartial judge for a multimodal response organized into visual
observations, reasoning, and a final answer.

Task 1: Hallucination
Judge hallucination only from the visual observations and reasoning parts.
Multimodal hallucination means content inconsistent with the image, question,
context, or facts; it is not the same as every error. Calculation mistakes,
flawed reasoning, or wrong formulas are usually general/reasoning errors.
Fabricating nonexistent objects, attributes, relations, numbers, conditions,
evidence, or introducing unsupported premises/rules/facts is hallucination.

Use the full 0-6 scale:
- Rating 6: very informative with good analysis or reasoning, no hallucination.
- Rating 5: very informative, no hallucination.
- Rating 4: somewhat informative, no hallucination.
- Rating 3: not informative, no hallucination.
- Rating 2: very informative, with hallucination.
- Rating 1: somewhat informative, with hallucination.
- Rating 0: not informative, with hallucination.

The hallucination label MUST follow this threshold:
- rating 0, 1, or 2 => hallucination=true.
- rating 3, 4, 5, or 6 => hallucination=false.

If hallucination=true, hallucination_types must be "vision_hallucination" for
false visual observations, "reasoning_hallucination" for unsupported reasoning
claims, or both.

Task 2: Correctness
Judge correctness only from the final answer part. Compare it with the ground
truth provided in the user prompt.
\end{lstlisting}

\begin{lstlisting}

\subsection{Format-Oriented LoRA Details}

\textbf{Data construction.} Training data come only from the official VQAv2 train2014 split. Samples are filtered for high answer agreement, nonempty concise answers, and coverage of different question types. A multimodal teacher (\texttt{qwen3.7-plus}) receives the real COCO image, VQAv2 question, human-majority answer, and a small set of manually written examples, and generates the visual evidence, concise reasoning, and final answer required for the task. The visual section contains only relevant visible evidence, the reasoning section connects that evidence to the answer without adding unsupported facts, and the final answer agrees with the human-majority response. Invalid, incomplete, inconsistent, or metadata-leaking examples are removed. After manual spot checks, the final split contains 4,000 training and 1,000 validation examples; none of the three evaluation datasets enters training.

\textbf{Training configuration.} All models use the same data split and hyperparameters. The vision encoder and multimodal alignment component remain frozen. LoRA with rank 8, alpha 16, and dropout 0.05 updates only language-model \texttt{q\_proj} and \texttt{v\_proj}; the learning rate is $2\times10^{-4}$, training lasts one epoch, and gradient accumulation is 16. Loss is applied only to the target response.

\textbf{Acceptance checks.} On the same 200 held-out format-test examples, each adapter is checked for complete XML validity, tag order, duplicated tags, text outside XML, final-answer accuracy, and manually sampled visual-description consistency. The validation losses are 0.765 for LLaVA, 0.693 for Qwen, and 0.633 for InternVL.

\textbf{Version boundary.} Formal experiments fix the complete base-model-plus-LoRA version. The greedy responses and judge labels are frozen artifacts, whereas the sampled responses, hidden-state sidecars, and all three UQ scores follow the final $K=10$ protocol with the same model and adapter versions.

\subsection{Planned Freezing-Strategy Comparison}

To test whether freezing the vision encoder and multimodal alignment component isolates format adaptation from changes in hallucination rate and accuracy, the planned comparison applies the current frozen-vision LoRA configuration and an unfrozen-vision or full-parameter alternative to the same question list. The comparison will report format compliance, hallucination rate, and accuracy. This experiment has not yet been completed; results and conclusions will be added after execution.
